# 短篇 · 全篇批量写

从起始场景到结束场景，以场景批为单位循环：写→check→盲审→通过→下一批。

写和审由两个**不同**的子 agent 完成，严禁同一 agent 既写又审。

默认每批写 5 个场景。

## 调用方式

```
参数：项目路径 [起始场景] [结束场景]
示例：短篇/言情/我的项目/ 1 10   → 写场景1到10
      短篇/言情/我的项目/ 3 7     → 写场景3到7
      短篇/言情/我的项目/         → 从场景1写到全部完成
```

## 逐批循环流程

### 1. 加载上下文

```bash
# 查看进度
python <skill_dir>/batch.py {项目路径} status

Read {项目路径}/场景规划.md        — 全篇场景清单、付费墙、节奏控制
Read {项目路径}/工艺约束.md         — 继承链 + 平台规则 + 自定义覆盖

# 加载工艺约束（自然语言）
python 短篇/工艺/约束体系/craft_cli.py --natural base --with-project {项目路径}
```

### 2. 写一批场景（子 agent A）

spawn 全新子 agent，传递以下指令：

```
你负责写场景{X}到场景{Y}，追加到 {项目路径}/正文.md。

严格遵守以下规则（从 craft_cli.py 获取的工艺约束）：
- 场景编号单独一行，阿拉伯数字（1 2 3），全篇连续
- 场景之间空行分隔
- 正文无章节号（不写 第N章）
- 对话符号按工艺约束
- 每段不超过工艺约束的句数
- 每场景字数在工艺约束范围内
- 禁用词列表
- 过渡词控制

先读前文（已有场景）保持语感连贯。
```

### 3. 机械检查

```bash
python <shortstory-write_dir>/check.py {项目路径}/正文.md --project {项目路径}
```

不通过 → 返回步骤 2 修改。通过 → 下一步。

### 4. 盲审（子 agent B，全新）

spawn **全新**子 agent（不可复用写章的 agent），传递：

```
你负责盲审场景{X}到场景{Y}。加载 skill shortstory-review 执行双路审查：
- 硬规则：对照工艺约束逐条检查（禁用词、段落句数、场景字数、对话符号等）
- 软规则：读参考文前 2000 字，给语感/自然度/节奏/阅读感评分
- 合规审查：对照 craft.yaml 检查清单逐项确认
- 输出 JSON 审查报告到 {项目路径}/审查报告/场景{X}-{Y}_审查报告.json
```

### 5. 判定

- **审查通过**（硬规则零阻断 + 软规则四项均 ≥6/10 + 合规率 ≥80%）→ `batch.py {项目路径} advance` 推进到下一批
- **审查阻断** → 记录审查意见，返回步骤 2 修改后再审
- **同一批场景连续阻断 3 次** → 在进度文件中标记 `blocked`，跳过继续下一批

### 6. 下一批

重复 1-5，直到结束场景完成。

## 异常处理

| 情况 | 处理 |
|------|------|
| 某批反复 blocked ≥3 次 | 标记 `blocked`，跳过继续下一批 |
| 正文.md 被意外清空 | 检查文件完整性，从 git 恢复 |
| 用户手动修改了正文 | 重新跑 check.py + 盲审 |
